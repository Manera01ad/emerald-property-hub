# Repository map

Where everything lives. Read this before a multi-file change, then load the skill
for the area you are touching.

## Root

| Path | What |
| --- | --- |
| `src/` | the app: TanStack Start routes, components, pure logic |
| `src/routes/` | file-based routes (`routeTree.gen.ts` is generated) |
| `src/lib/` | business and UI logic, flat by feature (see conventions below) |
| `src/components/` | shared components; `ui/` is the generated component kit |
| `src/integrations/supabase/` | Supabase clients, auth middleware, generated DB types |
| `e2e/` | Playwright browser tests |
| `scripts/` | `cto/` agent harness, `sql-check/` migration harness, `verify-journeys.mjs` evidence generator |
| `supabase/config.toml` | one line (`project_id`); not a schema source |
| `drizzle/` | hand-written SQL migrations (`migrations/` applied, `pending/` not) plus a blank `schema.ts` stub |
| `docs/` | product and operations documents; index in `docs/README.md` |
| `test-evidence/` | committed screenshots (generated output) |
| `.agents/skills/` | this directory: area instructions |
| `.github/` | workflows plus `CODEOWNERS` (Tier 3 paths) |

Config files stay at the root: `vite.config.ts`, `vitest.config.ts`,
`playwright.config.ts`, `tsconfig.json`, `eslint.config.js`, `drizzle.config.ts`,
`components.json`, `bunfig.toml`. Do not move them into a subfolder.

## `src/lib` naming conventions

The folder is flat on purpose; the suffix is the contract.

| Pattern | Meaning |
| --- | --- |
| `*.ts` (for example `buyer.ts`, `visibility.ts`) | pure rules, importable anywhere |
| `*.functions.ts` | TanStack server function (client-callable, server-executed) |
| `*.server.ts` | server-only module; never import it from a component |
| `*-data.ts` | static data or a compatibility shim for a table absent from generated types |
| `*.test.ts(x)` | colocated unit test |

## Tests

Five locations, all valid: colocated `src/**/*.test.ts(x)`, cross-cutting tests in
`src/test/`, `node:test` suites in `scripts/cto/*.test.mjs`, Playwright specs in
`e2e/`, and the evidence generator `scripts/verify-journeys.mjs`.

## Generated files: do not hand-edit

- `src/routeTree.gen.ts` (TanStack Router, regenerated by dev/build)
- `src/routes/mcp.ts` and `src/routes/[.well-known]/oauth-protected-resource.ts`
  (produced by the `@lovable.dev/mcp-js` Vite plugin)
- `.lovable/mcp/manifest.json` (same plugin)
- `src/integrations/supabase/types.ts` (generated from the live project)

If one of these needs a change, change the source or the command that generates
it, not the output.
